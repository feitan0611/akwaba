# ADR 0004 — Base de connaissances et RAG

- **Statut** : accepté — fonctionnalité optionnelle (cahier §5.2 « enrichissement de la base
  de connaissance »), **domaine à valider avec le formateur**
- **Date** : 2026-09-28

## Contexte

Le LLM répond uniquement avec ses connaissances générales : il ne connaît ni les services
locaux, ni les informations propres au public visé, et peut inventer. Le cahier demande des
réponses « exploitables » et des limites présentées honnêtement.

## Décision

1. **Base de connaissances en Markdown** dans `knowledge/`, versionnée dans Git, rédigée en
   français (langue pivot). En-tête obligatoire `title` + `source` : aucune information sans
   source (même règle que le corpus audio). Validation automatique, erreur explicite sinon.
2. **Découpage** par sections Markdown, passages ≤ 800 caractères, titre du document et de la
   section répétés dans chaque passage (contexte pour l'embedding et le LLM).
3. **Embeddings** derrière une interface `Embedder` :
   - moteur `local` : **`bge-m3` via Ollama** — multilingue (bon en français), 1,2 Go,
     cohérent avec le LLM déjà servi par Ollama, sans nouvelle dépendance Python ;
   - moteur `mock` : embedding lexical haché, sans téléchargement (tests, CI).
4. **Index vectoriel = fichier JSON** (`data/rag_index/`, hors Git) + recherche exhaustive
   par similarité cosinus en Python pur. Suffisant jusqu'à quelques milliers de passages ;
   une base vectorielle (FAISS, Chroma) serait prématurée.
5. **Reconstruction automatique** de l'index dès qu'un document change (empreinte des
   fichiers vérifiée à chaque recherche) ou que le modèle d'embedding change (un index par modèle).
6. **Seuil de pertinence** (`min_score`, propre à chaque modèle) : sous le seuil, aucun passage
   n'est transmis et le LLM répond sans la base, en le signalant. Les **sources** sont
   renvoyées par l'API (`sources`) et affichées dans l'interface.
7. Endpoints `GET /knowledge`, `POST /knowledge/search` (scores, pour régler le seuil),
   `POST /knowledge/reindex` ; outil `python -m app.rag`.

## Conséquences

- ➕ Réponses ancrées dans des informations vérifiées, avec leur source.
- ➕ L'équipe enrichit la base sans toucher au code.
- ➖ **La qualité dépend entièrement du contenu** : il faut choisir un domaine (santé,
  agriculture, démarches…) et produire des documents fiables et sourcés. Seul un document
  factuel sur l'assistant lui-même est fourni pour l'instant.
- ➖ Le seuil `min_score` (0,45 par défaut pour bge-m3) est une valeur de départ : à
  calibrer sur des questions réelles avec `POST /knowledge/search`.
- ➖ Un modèle de 3 milliards de paramètres peut encore s'écarter des extraits : l'évaluation
  humaine des réponses reste nécessaire.
